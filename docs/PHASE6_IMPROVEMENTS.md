## P0: 强烈推荐（课程汇报核心亮点）

### 1. 前端可视化

**为什么是亮点**: 直观展示流水线工作原理，评委/老师一眼就能理解项目价值

**技术方案**:

```
技术栈推荐：
- 后端: Rust + WebAssembly (复用现有模拟器核心)
- 前端: React + D3.js (可视化)
- 通信: WebSocket (实时状态推送)
```

**可视化内容**:

| 组件 | 描述 | 复杂度 |
|------|------|--------|
| 流水线动画 | IF→ID→EX→MEM→WB 指令流动 | 中 |
| 寄存器面板 | 32 个通用寄存器实时值 | 低 |
| 内存视图 | 内存区域十六进制显示 | 低 |
| CSR 面板 | 关键 CSR 寄存器状态 | 低 |
| 冒险可视化 | 数据冒险/控制冒险高亮 | 中 |
| 前递路径 | EX/MEM 前递动画 | 中 |

**实现步骤**:

1. 添加 `cpu.state_snapshot()` API 导出 CPU 状态
2. 实现 WebSocket 或 HTTP 轮询接口
3. 创建前端可视化组件
4. 添加单步执行、暂停、复位控制

**详细设计**: 见 [VISUALIZATION_DESIGN.md](./VISUALIZATION_DESIGN.md)

---

### 2. 性能监控与基准测试

**为什么是亮点**: 用数据说话，展示模拟器的性能特征

**实现内容**:

#### 性能计数器 (RISC-V HPM)

| CSR 地址 | 名称 | 说明 |
|----------|------|------|
| 0xB00 | mcycle | 周期计数器 |
| 0xB02 | minstret | 已完成指令计数器 |
| 0xB03-B1F | mhpmcounter3-31 | 可编程事件计数器 |

#### 关键指标

| 指标 | 计算方式 | 教育意义 |
|------|----------|----------|
| IPC | instructions / cycles | 流水线效率 |
| 分支预测准确率 | correct / total | 控制冒险影响 |
| Load-Use 暂停次数 | stall cycles | 数据冒险影响 |

#### 基准测试程序

- **CoreMark**: 嵌入式标准基准
- **Dhrystone**: 经典整数基准
- **自写测试**: 斐波那契、排序算法等

**详细设计**: 见 [PERFORMANCE_MONITORING.md](./PERFORMANCE_MONITORING.md)

## P1: 推荐实现（展示技术深度）

### 3. M 扩展 (乘除法指令)

**教育价值**: 展示多周期指令如何在流水线中执行

**指令列表**:

| 指令 | 功能 | 说明 |
|------|------|------|
| MUL | rd = (rs1 × rs2)[31:0] | 乘法低位 |
| MULH | rd = (rs1 × rs2)[63:32] | 乘法高位 (有符号) |
| MULHSU | rd = (rs1 × rs2)[63:32] | 有符号 × 无符号 |
| MULHU | rd = (rs1 × rs2)[63:32] | 无符号 × 无符号 |
| DIV | rd = rs1 / rs2 | 有符号除法 |
| DIVU | rd = rs1 / rs2 | 无符号除法 |
| REM | rd = rs1 % rs2 | 有符号取余 |
| REMU | rd = rs1 % rs2 | 无符号取余 |

**实现要点**:

- 乘法: 32×32→64 位结果，需要多周期
- 除法: 迭代算法，约 32 周期
- 流水线集成: 可能需要暂停

**复杂度**: 低（约 200-300 行代码）

## P2: 可选挑战（时间充裕时）

### 4. NPU/ML 扩展

**亮点**: 结合 AI 热点，展示创新性

**可行方案**:

| 方案 | 内容 | 复杂度 | 周期 |
|------|------|--------|------|
| 基础 MAC | 乘累加指令 | 低 | 1 周 |
| 矩阵操作 | 简单矩阵乘法 | 中 | 2-3 周 |
| 神经网络 | 简单 CNN 推理 | 高 | 4-6 周 |

**最小可行演示**:

```asm
# 自定义扩展指令
mac  rd, rs1, rs2  # rd = rd + rs1 * rs2
relu rd, rs1       # rd = max(0, rs1)
```

运行一个简单的 MNIST 数字识别 demo

---

### 5. Sv32 虚拟内存

**教育价值**: 理解现代操作系统的内存管理

**实现内容**:

- 页表结构 (两级页表)
- TLB 缓存
- 地址翻译
- 页错误异常

**复杂度**: 高（约 1000-2000 行代码）

**关键数据结构**:

```
Sv32 页表项 (PTE):
┌─────────────────────────────────────────────────────┐
│ PPN[1] (12 bits) │ PPN[0] (10 bits) │ RSW │ D A G U X W R V │
└─────────────────────────────────────────────────────┘
```

## P3: 进阶扩展

### 7. C 扩展 (压缩指令)

**特点**: 16 位指令，提高代码密度

**指令示例**:

- `c.addi rd, imm` - 等价于 `addi rd, rd, imm`
- `c.li rd, imm` - 等价于 `addi rd, x0, imm`
- `c.j offset` - 等价于 `jal x0, offset`

**复杂度**: 中（需要修改译码器）

---

### 8. 多核支持

**挑战**: 缓存一致性、同步机制

**实现内容**:

- 多个 Hart (硬件线程)
- 核间中断 (IPI)
- 共享内存管理
- 原子操作 (A 扩展)

**复杂度**: 很高

## 选定实施方案

### 第一阶段：核心功能（必做）

**重点**: 前端可视化 + 性能监控 + M 扩展

**周期**: 4-5 周

```
Week 1: M 扩展 (乘除法指令)
Week 2: 性能计数器 + CoreMark 集成
Week 3: WebSocket API + 状态导出
Week 4-5: 前端可视化界面
```

### 第二阶段：挑战功能（时间充裕时）

**顺序**: Sv32 → miniOS → NPU

```
Week 6-8: Sv32 虚拟内存
Week 9-10: 简单 OS 内核 (基于 rCore-Tutorial)
Week 11-13: NPU/ML 扩展 + MNIST demo
```
