### 第 2 页：技术选型（为什么是 RISC-V + Rust）（约 45 秒）

**页面核心内容**：
- 选择 **RISC-V RV32I**：
  - 规范开放、资料完备，便于课程对照讲解；
  - RV32I 指令规模适中，适合课设周期；
  - 原生支持 **M/S/U 特权级**，便于 OS 方向扩展；
  - 可借助 **QEMU** 做差分验证。
- 选择 **Rust**：
  - **所有权模型** 在编译期控制内存安全；
  - **Trait 零成本抽象** 便于模块解耦；
  - `match + Result` 很适合指令译码与错误传播。

**调研对标结论（并入展示）**：
- 对标 NEMU：强调“**可验证性闭环**”（DiffTest + 调试器 + 快照）；
- 对标 QEMU：强调“**可集成调试能力**”（GDB/RSP 完整性）与性能归因；
- 对标 Spike：强调“**语义正确性回归**”（分层对比 + 失败复盘）。

**实现对应（可点到文件）**：
- 指令与执行：`src/instruction/*`、`src/cpu/core.rs`
- 抽象接口：`src/traits/*`

**亮点表达**：
- “选型不是追新，而是服务于 **可实现性 + 可验证性 + 可扩展性**。”

---

### 第 3 页：系统架构与模块分层（约 45 秒）

**页面核心内容**：
- 架构模式：基于 **Memory-Mapped I/O**，由 **Bus** 统一挂载 CPU/内存/外设。
- 四层结构：
  1. **核心执行层**：`cpu/`、`instruction/`
  2. **系统支撑层**：`memory/`、`interrupt/`、`peripheral/`
  3. **调试验证层**：`debug/`、`difftest/`、`loader/`
  4. **展示交互层**：`visualize/` + `frontend/`
- 关键接口：
  - `Memory` trait 统一读写语义；
  - `Peripheral` trait 统一外设接入；
  - `ExecutionModel` 支持执行模型切换。

**具体实现亮点**：
- 新外设接入只需“地址映射 + trait 实现 + bus 挂载”，扩展路径清晰。

---

### 第 4 页：CPU 核心实现（流水线与冒险处理）（约 65 秒）

**页面核心内容**：
- 5 级流水线：**IF → ID → EX → MEM → WB**。
- 三类冒险处理：
  - **数据冒险（RAW）**：优先 **Forwarding**；
  - **Load-Use 冒险**：插入停顿气泡（NOP）；
  - **控制冒险**：静态预测不跳转 + 预测失败冲刷。
- 结构冒险处理：通过指令/数据路径解耦尽量规避冲突。

**具体实现细节（建议上图）**：
- 前递路径：EX/MEM、MEM/WB 到 ID/EX 的旁路通道；
- 冲刷策略：分支判定后清空错误路径流水线寄存器；
- 关键目标：在保证语义正确前提下提高 IPC。

**难点说明**：
- **Load-Use** 不能靠前递完全解决，必须精准控制停顿周期。

---

### 第 5 页：特权级、异常与中断实现（约 55 秒）

**页面核心内容**：
- 特权级：完整实现 **M/S/U 模式** 与 `ecall/mret/sret` 切换语义。
- Trap 流程：
  - 保存故障上下文到 `mepc/mcause/mtval`；
  - 更新 `mstatus`；
  - 跳转 `mtvec/stvec` 处理入口。
- 中断体系：
  - **CLINT** 负责本地时钟/软件中断；
  - **PLIC** 负责外部中断仲裁；
  - 支持 `mideleg/medeleg` 委托机制。

**具体实现亮点**：
- 同时兼顾单周期与流水线模型下的 trap 语义一致性。

**难点说明**：
- 异常与中断的优先级、委托路径、返回路径必须严格一致，否则会出现隐蔽状态错误。

## 二、5 分钟讲稿（丰富版，可直接读）

大家好，我的开题项目是 **myCPU：面向课设的 RISC-V RV32 模拟器**。

这个项目要解决一个很实际的问题：在课程学习中，**指令系统**、**流水线**、**异常中断**、**外设调试** 往往是分章节学习的，大家很难形成“一个完整 CPU 系统到底如何协同工作”的整体认知。我的目标是做一套可以完整串联这些知识点的平台，也就是从 **ISA 执行** 到 **流水线实现**，再到 **特权级与中断**、**调试验证**、**可视化展示** 的工程闭环。

先说技术选型。ISA 选择 **RISC-V RV32I**，主要是因为它规范开放、资料完整、复杂度对课程项目友好，而且特权级体系规范，后续可以自然扩展到 OS 场景。语言选择 **Rust**，核心考虑是两点：第一，所有权与类型系统能在编译期约束很多底层错误；第二，Trait 抽象让模块边界更清晰，后续扩展外设和执行模型时改动范围更可控。

在选型之外，我们还做了对标调研：NEMU 给我们的启示是“先把可验证性闭环做扎实”，QEMU 提醒我们“调试接口必须可集成到真实工具链”，Spike 则强调“语义正确性需要稳定回归机制”。所以这个项目从一开始就不是单纯堆功能，而是以“可验证、可调试、可回归”为主线推进。

在整体架构上，系统采用 **Memory-Mapped I/O**。我用一条统一 **Bus** 连接 CPU、内存与外设，外设通过地址映射接入，不需要改动核心执行逻辑。模块上分四层：核心执行层负责 `instruction` 与 `cpu`，系统支撑层负责 `memory/interrupt/peripheral`，工具层提供 `loader/debug/difftest`，展示层由 `visualize + frontend` 组成。这样做的好处是：每层职责明确，既方便定位问题，也方便逐步扩展。

实现里最难的部分是 **流水线与异常路径**。流水线是经典的 **IF/ID/EX/MEM/WB** 五级。数据冒险优先采用前递，但 **Load-Use** 冒险不能只靠前递解决。比如 `lw x5, 0(x1)` 后紧跟 `add x6, x5, x7`，第二条指令在需要 `x5` 时，数据还没从 MEM 阶段返回，这时必须插入一个气泡周期，保证语义正确。控制冒险方面采用静态预测不跳转，预测失败时冲刷错误路径流水线寄存器，避免错误状态传播。

特权与异常中断方面，我实现了 **M/S/U 三种特权模式** 和 `ecall/mret/sret` 的切换语义。Trap 处理按照规范写入 `mepc/mcause/mtval`，并跳转到 `mtvec/stvec`。中断系统由 **CLINT + PLIC** 构成，同时支持 `mideleg/medeleg` 委托机制。这里的重点是保证“单周期模型”和“流水线模型”在 trap 语义上一致，否则调试时会出现非常隐蔽的行为偏差。

项目亮点主要有四个。第一，**DiffTest**：与 QEMU 做逐步对比，快速发现行为不一致。第二，**GDB Remote**：支持断点和单步，调试链路完整。第三，**HPM 性能监控**：可输出 IPC、暂停率、分支准确率等指标，让性能分析有数据依据。第四，**Trait 驱动的可扩展架构**：新增外设时基本遵循“地址映射 + trait 实现 + bus 挂载”的固定路径。

另外，调研中识别的高优先级风险项，例如 ELF 启动入口语义、GDB RSP 核心命令占位、CLINT 对齐访问语义，已经在路线图中逐项闭环，这部分会作为“工程质量”证据在答辩中重点说明。

计划方面按照课设统一推进 **第4-8周**：第4周完成基础框架与 RV32I，第5周完成流水线与冒险处理，第6周完成特权与中断，第7周完成外设与调试验证，第8周完成演示封装与回归矩阵。

总结一下，我希望把 myCPU 做成一套 **架构可解释、实现可验证、结果可复现** 的课程级平台，不仅能演示“跑起来”，更能解释“为什么这样设计、如何证明正确”。谢谢大家。
